## 首要交付闭环

1. 安装明确版本，保存工作后重启 Rhino，核对加载消息。
2. 使用合法拥有的模型资产，在同一空间场景展示最多三个候选、切换预览和准确设置高度/位置/角度。
3. 实际切换三个候选（不能用单候选的参数变化替代），接受候选成为独立 Block；检查源几何不变、只产生一次 Undo、Redo 后恢复。
4. 保存并重开 `.3dm`，确认模型与材质、贴图依旧可用。
5. 展示已生成任务恢复或缓存重用，没有再次生成或重复收费。
6. 检查失败回滚及 Tripo 同宿主共存，保留错误日志与场景前后对象数量。
7. 单独录制真实文字/单图生成流程，遮蔽 API Key 和私人账户信息；真实收费任务只在用户明确操作后进行。

## 3 分钟演示脚本

- 0:00–0:20：空间设计者在 Rhino 中挑选物件的具体问题，展示完成场景。
- 0:20–0:55：实际生成任务与就绪资产，清楚区分 OAuth 可选和区域 API Key 必需。
- 0:55–1:40：同位置比较三个候选，修改高度/角度后接受一个，解释原位比较对设计决策的价值。
- 1:40–2:15：Undo/Redo、保存重开与材质验证，以真实运行画面呈现。
- 2:15–2:40：展示原任务下载恢复和缓存重用，不重复生成。
- 2:40–3:00：安装方式、源码链接、当前支持平台及准确的限制。

报告建议 6 页：用户问题、完成场景、工作流与迭代对比、可靠性机制、真实验收结果、安装与后续计划。未完成的测试使用“待验证”，不得用构想图或模拟画面充当真实运行证据。
